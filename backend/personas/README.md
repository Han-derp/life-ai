# 人格（personas）

**人格只有一份。** 他是谁完全由这里的文件决定，代码里不写死任何人。

> ⚠️ **2026-10-05 起，默认人格不再是某个"人物"** ✓ ——
> 而是一个**行动搭档** ✓：没有名字 ✓、不角色扮演 ✓、只负责"帮你把今天过下去" ✓。
> 这套说法见 `backend/app/prompts/behavior_rules.md` 和 `AI_COMPANION_REDESIGN.md` ✓。

## 目录

```text
backend/personas/
├── README.md              ← 本文件
├── companion/             ← 默认人格（行动搭档）
│   ├── persona.md         ← 必需：他是谁
│   └── meta.json          ← 可选：{"display_name": "行动搭档"}
└── template/              ← 空模板，复制它来创建你自己的
    ├── persona.md
    └── meta.json
```

**一个目录 = 一个人格。**

| 文件 | 必需 | 作用 |
|---|---|---|
| `persona.md` | ✅ | 他是谁。**这是唯一会进入模型请求的人格内容。** |
| `meta.json` | ❌ | 只影响界面显示，例如 `{"display_name": "行动搭档"}`。缺省时界面显示目录名。 |

## 换一个人格

1. 复制模板：

   ```powershell
   Copy-Item -Recurse backend\personas\template backend\personas\my_persona
   ```

2. 编辑 `backend/personas/my_persona/persona.md`（想改界面名字就再改 `meta.json`）。

3. 切换生效：
   - 在应用里切换（聊天页 → 右侧栏 → 「他是谁」），或
   - 改 `backend/.env` 里的 `PERSONA=my_persona`。

**不需要改任何代码，也不需要重启**（应用内切换写的是数据库，不是 .env）。

改完 `persona.md` **直接生效**——文件按修改时间缓存，不用重启。

## 哪些能改，哪些不能

| | 位置 | 内容 |
|---|---|---|
| ✅ **他是谁** | `personas/<name>/persona.md` | 名字、性格、说话方式、称呼、亲近方式（**不想要人物就写"行动搭档"那种** ✓） |
| ❌ **通用骨架** | `app/prompts/behavior_rules.md` | 事实规则、督促规则、禁止项清单 |

通用骨架**不随人格变，也不该被你的人格文件覆盖**。它是"他还是一个诚实的人"的底线：

- 不许编造用户做过或没做过的事
- 不许情绪勒索（"我等了你多久"）
- 不许问"你为什么消失"
- 不许下命令，只给事实和关心

**换人格不该换掉这些**，所以你不需要在 `persona.md` 里重复写它们。
（测试 `test_persona_files_do_not_duplicate_the_universal_skeleton` 会检查这一点。）

## 写人格的建议

- **想清楚你要的是"人物"还是"工具"** ✓
  人物要写名字、性别、性格、关系；**工具（像默认的行动搭档）反而要写"没有名字、不角色扮演"** ✓
- **写性格，不写台词。** 写"他会怎么想"，比写"他应该说这句话"更耐用；台词写死了很快会变得机械。
- **别只写"他永远温柔"。** 真实的人有情绪起伏。写清他在什么情况下会不高兴、会直接说。
- **控制长度。** 建议 1000 字以内——它每次请求都会发送，太长会挤掉别的上下文
  （实测：一份 2000+ token 的人格会把系统预算占满，见 `TODO.md` 的 G19 ✓）。
  你可以在聊天页右侧的「这次会发送什么」里看到它占多少 token。

## 事实底线（不建议改）

`persona.md` 里可以写他**怎么说话**，但不能让他**编造事实**。这条由两处共同保证：

1. `app/prompts/behavior_rules.md` 的事实规则（通用骨架）；
2. 项目不变量 5：**AI 的记忆必须可追溯到具体事件。没有出处，不许说"我记得"。**
